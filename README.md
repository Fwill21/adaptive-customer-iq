# Otto's Guidance

Lovable Prompt

CSP on AINPX Future Vision Leadership Experience

Create a polished, high-fidelity interactive leadership storytelling prototype for a future ServiceNow Customer Success Platform experience on AINPX.

This is NOT a traditional dashboard redesign.

The concept represents a future-state personalized AI operating environment for customer success, where AI is the primary driver of the experience.

The prototype should visually communicate how:

Otto acts as the primary AI relationship and orchestration layer.

Ten specialized AI agents operate behind Otto.

Agents continuously monitor, analyze, prepare, coordinate, and act.

Users do not manually select or manage agents.

The AI environment understands customer context continuously.

The experience adapts depending on the user's role, responsibility, customer, and current moment.

Customer success work moves seamlessly across CSMs, TSMs, AEs, Support, Services, BPCs, and other roles.

AI reduces cognitive and operational work.

Horizon 2.0 patterns are used to create a simplified, progressive, contextual experience rather than a dense dashboard.

The platform shifts customer success from reactive work toward proactive, continuously aware orchestration.

EXPERIENCE PRINCIPLE

The central idea is:

The user should not have to navigate the system to understand the customer. The system should organize itself around what the user needs to know and do now.

Avoid designing a traditional workspace with many cards, widgets, tables, sidebars, or navigation elements.

Prioritize:

contextual intelligence

progressive disclosure

clear hierarchy

conversational interaction

recommendations

explanations

next best actions

dynamic adaptation

confidence and evidence

human control

The experience should feel calm, premium, intelligent, and highly focused.

PRIMARY PERSONA

Use a Customer Success Manager as the narrative anchor.

However, clearly establish that the platform is role-agnostic and capable of adapting to other customer-facing roles.

Example customer:

Acme Corporation

The CSM manages several strategic enterprise accounts.

GLOBAL EXPERIENCE

Create a persistent Otto interaction layer.

Otto should feel integrated into the product experience rather than existing only as a chatbot panel.

Otto can appear through:

conversational prompts

contextual summaries

recommendations

proactive notifications

generated briefings

explanations

next actions

Otto should communicate naturally and concisely.

Do not make Otto overly conversational when a direct interface action is more appropriate.

Use conversation when the user needs to explore, ask questions, refine, or request an outcome.

Use interface controls when an action can be completed directly.

AI ARCHITECTURE

Represent three conceptual layers.

Layer 1: Otto

Primary orchestrator.

Understands:

person

role

current task

customer

workflow

history

current context

Otto determines what should happen next.

Layer 2: Specialized Agents

Show ten specialized agents as a coordinated intelligence network.

Do not require the user to manually choose them.

For prototype purposes, agents can include concepts such as:

Customer Health Agent

Adoption Agent

Risk Agent

Opportunity Agent

Success Planning Agent

Meeting Intelligence Agent

Customer Context Agent

Support Intelligence Agent

Value Realization Agent

Coordination Agent

Agent names are placeholders and should be easy to change later.

Use agent activity primarily as a background intelligence visualization.

Examples:

"4 agents contributed to this recommendation."

"Adoption, Health, and Risk agents detected this change."

Avoid making agents look like ten separate products.

Layer 3: AI Environment

The intelligence is informed by:

customer data

product adoption

health

support activity

success plans

customer goals

meetings

communications

tasks

workflows

commitments

knowledge

account history

enterprise systems

This environment operates continuously.

STORY STRUCTURE

Build the prototype as a guided quarter-long story.

Include a presentation/demo mode with clear progression between the following moments.

MOMENT 1

Start My Quarter

Create a future-state landing experience.

Do NOT create a traditional dashboard.

Primary question:

What needs my attention right now?

Otto greets the CSM and provides a prioritized orientation.

Example:

"Good morning. Three accounts need your attention this week.

Acme's adoption has slowed.

Globex has a new executive sponsor.

Contoso is approaching an important success milestone."

Show:

prioritized accounts

reason each account matters

relevant quarter goals

upcoming customer milestones

meaningful changes

recommended actions

Provide a conversational prompt:

What should I focus on first?

When selected, Otto should recommend Acme and explain why.

Create a clear visual hierarchy.

The user should understand the situation within seconds.

MOMENT 2

Something Changed

Transition into Acme Corporation.

The AI environment detects:

Adoption declined 18% over the past three weeks within Acme's primary deployment group.

Present this as contextual intelligence, not a generic alert.

Show progressive layers:

What changed

Adoption decreased 18%.

Why it matters

A strategic customer milestone may be at risk.

Evidence

Usage decline correlates with recent configuration and support activity.

Recommended action

Investigate with the Technical Success Manager before the next customer meeting.

Include an expandable section:

How did Otto determine this?

When opened, reveal that multiple agents contributed.

Example:

Adoption Agent
Customer Health Agent
Risk Agent
Customer Context Agent

Display:

4 agents contributed to this recommendation

This visualization should help leadership understand the architecture without disrupting the user experience.

MOMENT 3

Coordinate the Response

Otto recommends:

Recommended response

Ask the TSM to investigate the adoption decline.

Keep the AE informed because this could affect expansion.

Prepare an adoption recovery plan before the upcoming customer meeting.

Primary action:

Coordinate response

When selected, animate the environment coordinating the work.

Show:

CSM → Otto → Agent Network → TSM / AE

Make the movement of context visible.

The CSM should not manually compose tasks or transfer information.

Show Otto preparing the necessary context automatically.

Then provide a brief role-switch interaction.

Allow the demo to switch from:

CSM View

to:

TSM View

The TSM experience should immediately reorganize around their responsibility.

Show:

technical problem

relevant customer context

supporting evidence

expected outcome

recommended investigation

Do not simply show the same screen with different data.

Demonstrate true role-aware personalization.

Include a subtle label:

Same customer. Same environment. Different responsibility.

MOMENT 4

Prepare Me for the Customer

Return to the CSM.

The TSM investigation has identified a likely cause and recommended remediation.

The customer meeting is approaching.

Create a conversational interaction:

CSM: Prepare me for my meeting with Acme.

Otto generates a meeting briefing.

Structure the briefing around decisions rather than data.

Include:

What changed

Adoption decreased due to a configuration issue.

Customer impact

A strategic milestone could slip two weeks.

What we've done

The TSM identified the technical cause and created a remediation path.

What we need from the customer

Confirm deployment timing and stakeholder availability.

Recommended conversation

Acknowledge the issue.

Explain what caused it.

Present remediation.

Reconfirm the success milestone.

Agree on next actions.

Likely customer questions

"What does this mean for our timeline?"

"Will additional technical resources be required?"

Allow the CSM to ask follow-up questions conversationally.

Example:

What is the biggest risk?

Otto should respond contextually.

POST-MEETING STATE

After the customer meeting, briefly show the system capturing the outcome.

Otto identifies:

decisions

actions

owners

deadlines

commitments

changes in customer expectations

Present:

Meeting outcomes captured

Provide a review-and-confirm interaction.

After confirmation, show:

3 commitments are now being monitored.

The CSM should not manually update several different systems.

This moment should feel fast and almost invisible.

MOMENT 5

Show the Value

Advance the timeline toward the end of the quarter.

Otto recognizes an upcoming Customer Value Review.

Present:

Your Acme Customer Value Review is approaching.

"I've prepared a draft value story based on this quarter's customer goals, activity, milestones, adoption, outcomes, and resolved issues."

Primary action:

Build value story

Create a value narrative including:

Customer goals

What Acme wanted to accomplish.

Progress

Key milestones and adoption progress.

Value realized

Specific measurable outcomes.

Challenges resolved

Include the adoption issue from Moment 2 and how the team responded.

Remaining risks

Any unresolved concerns.

Next-quarter opportunities

Recommended next priorities.

Show visually that this narrative was assembled from activity throughout the quarter.

Potential visual:

Quarter timeline

Start Quarter → Adoption Signal → Cross-Role Response → Customer Meeting → Recovery → Value Review

Use subtle agent markers beneath the timeline showing that specialized agents were continuously contributing.

FINAL REVEAL

After Moment 5, transition from the product experience into a leadership-level architecture visualization.

Show:

PERSON

↓

OTTO

↓

10 SPECIALIZED AGENTS

↓

AI ENVIRONMENT

Then surround the system with the supported roles:

CSM
TSM
AE
Support
Services
BPC
Other customer-facing roles

Label the overall environment:

CSP on AINPX

Add:

Powered by Horizon 2.0 interaction patterns

Primary closing statement:

From navigating customer success tools to operating within an intelligent customer success environment.

BEFORE / AFTER VIEW

Create a final leadership comparison.

TODAY

The person must:

Find information
Interpret signals
Coordinate people
Create artifacts
Track commitments
Reconstruct the customer story

FUTURE

The AI environment:

Understands context
Detects meaningful change
Coordinates intelligence
Prepares work
Maintains continuity
Builds the customer story

Use minimal text and strong visual contrast.

VISUAL DESIGN DIRECTION

The prototype should feel consistent with a future enterprise AI product built using ServiceNow Horizon 2.0.

Design qualities:

sophisticated

spacious

minimal

calm

intelligent

premium

contextual

enterprise-ready

Avoid:

consumer chatbot aesthetics

excessive gradients

neon AI imagery

floating AI orbs

robot imagery

overly futuristic sci-fi visual language

traditional dense dashboards

unnecessary side navigation

excessive cards

large amounts of competing information

Use progressive disclosure aggressively.

Each moment should begin with the minimum information needed to make a decision.

Allow deeper evidence and context to be revealed when requested.

AI VISUAL LANGUAGE

Develop a subtle visual language for AI activity.

Distinguish:

Otto

Visible orchestration and user interaction.

Agents

Background intelligence.

Awareness

Signals being continuously monitored.

Recommendations

AI-generated next best actions.

Human decisions

Actions requiring user confirmation.

Never make AI feel autonomous in ways that remove user control.

Show:

AI detects
AI recommends
Human reviews
AI executes or coordinates

when appropriate.

PRESENTATION MODE

Add a leadership presentation mode.

Provide navigation:

Previous
Next

Show the current story moment.

Include a small progress indicator:

01 Start My Quarter
02 Something Changed
03 Coordinate Response
04 Prepare for Customer
05 Show the Value

Allow the presenter to move through the story without navigating the full product manually.

Each presentation step should have a clean transition.

Avoid overly complex animation.

The narrative should be understandable even if the presenter only spends 30–60 seconds on each major moment.

OPTIONAL ARCHITECTURE OVERLAY

Add an optional toggle:

Show AI activity

When enabled, show which agents and roles are contributing behind the visible experience.

Example:

Visible experience:
Otto recommends investigating adoption decline.

AI activity overlay:

Customer Health Agent → detected health change
Adoption Agent → detected usage decline
Risk Agent → evaluated milestone impact
Customer Context Agent → connected support activity

Otto → synthesized recommendation

This is intended for leadership explanation.

It should not represent the normal end-user experience.

CORE DESIGN TEST

Every major screen must make four things clear:

What does this person need right now?

What does Otto understand?

What intelligence is operating behind the scenes?

What is easier or newly possible because of AI?

If a screen does not support one of these four questions, simplify or remove it.

The final prototype should sell the transformation from a role-based customer success workspace into a personalized, continuously aware, AI-driven customer success operating environment.
